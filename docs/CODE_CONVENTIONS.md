# 코드 컨벤션

## 자동 규칙

TypeScript `strict`, 인덱스/null·optional·미사용 검사와 ESLint·Prettier를 사용합니다. UTF-8, LF, 2칸 들여쓰기, 작은따옴표, 세미콜론, 후행 쉼표, 줄 길이 100자 기준입니다. 자동 포맷 결과를 우선합니다.

| 대상                   | 명명                                 |
| ---------------------- | ------------------------------------ |
| 파일/폴더              | kebab-case: chat-service.ts          |
| 클래스/타입/인터페이스 | PascalCase: ChatProvider             |
| 함수/변수              | camelCase: selectChat, currentId     |
| 공유 고정값            | UPPER_SNAKE_CASE: MAX_MESSAGE_LENGTH |
| 테스트                 | 대상 파일 + .test.ts                 |

모호한 축약어를 피하고 함수는 한 목적을 갖습니다. 조기 반환으로 중첩을 줄입니다. 타입 가져오기는 `import type`, 설명 주석은 제약/이유 중심으로 씁니다. 순환 참조와 무분별한 barrel export를 추가하지 않습니다.

## 타입·의존성

`any`, non-null assertion, 근거 없는 캐스팅을 사용하지 않습니다. 외부 입력은 `unknown`으로 받고 검증합니다. DOM 조회는 요소 종류를 확인합니다. 스냅샷과 요청은 읽기 전용으로 취급합니다. 내부 상태 변경은 스토어/유스케이스에서 담당합니다. 의존성은 생성자로 주입하고 전역 싱글턴·서비스 로케이터를 피합니다.

TypeScript는 API 응답을 런타임 검증하지 않습니다. 실제 HTTP 연동 시 JSON/SSE 검증은 별도로 추가해야 합니다.

## 비동기·에러

취소와 실패를 구분하고 예외 원문을 사용자에게 노출하지 않습니다. 요청 종료 시 소유권을 확인합니다. 이벤트 Promise는 경계에서 처리하며 의도적인 fire-and-forget만 `void`로 표시합니다. 이벤트·타이머·취소 리스너를 정리합니다. 재시도는 멱등성·중복 비용을 검토한 뒤 추가합니다.

실제 API 도입 시 사용자 안내와 서버 로깅을 분리하며 대화 원문·토큰을 로그에 넣지 않습니다.

## UI·리뷰

사용자·응답 데이터를 `innerHTML`로 넣지 않습니다. Markdown 도입 시 정화 정책과 회귀 테스트가 필요합니다. 의미 있는 버튼 이름, 키보드, 실제 한글 IME, 모바일, 200% 확대를 확인합니다. API 키는 프론트에 넣지 않습니다.

리뷰는 책임 경계, 동작, 오류·취소·경쟁 상태, 테스트의 실패 감지 능력, API 호환성, 의존성 추가 이유, 접근성을 봅니다. 무관한 정리·미요청 기능을 한 PR에 섞지 않습니다.
